Warrant System Canvas

The problem

AI agents commit money actions, such as credits and refunds, on evidence that is contested or out of date.

When agents or systems disagree, mechanics settle it: the last write or the most confident agent wins, and nothing records why.

The cost surfaces late, as reversals and credit leakage. How often this happens in enterprises is still unmeasured.

The product strategy

Enter CRM customer service in shadow mode as a vendor-neutral check on actions whose evidence spans several systems, then extend to other verticals.

Sell throughput first and risk second: more actions commit safely without a person, and each ruling becomes a rule the buyer can audit.

The user and their pain points

User: the support or applied AI engineer who sets what agents may do alone; the buyer is the VP of Support.

Money conflicts: a refund agent credits a flagged account, or two agents stack compensation in the same hour.

Stale evidence: an agent applies a superseded policy, or grants an SLA while billing shows the account past due.

Autonomy boundary: set too tight, the human queue grows; set too loose, reversals repeat.

Invisible until late: clawbacks surface at month-end close, with no record of what the agent relied on.

The desired solution, by phase

  • Intervene: act, gather or hold before commit: gate in v1 and v2, person's view in v3, live agent path in v4.
  • Learn: rulings become rules with an owner and expiry: scripted in v1, persisted in v2, real rulings from v3.
  • Prove: shadow report and kill switch for the buyer: planned for v4, then a pilot on real tickets.

1. The system

Warrant is a code pipeline with one model step, sitting between a support agent's money action and the systems that would be written. It is deliberately not an agent: no model chooses a tool or a path.

Design callout · decision, trade-off, conclusion · fit with the belief-state thesis

Decision. What the loop learns is stored as a standing rule with an owner and an expiry, never as a prompt edit.

Trade-off. A rule is crude: it matches on a pattern and cannot weigh evidence. In return it can be read, attributed, expired and diffed.

Conclusion. Rules are the seed of a belief store, but they are not one. They hold policy, not how far to trust a source or how fast a fact goes stale. Section 14 maps what a belief state would replace.

3. Risks and the recursive analysis

Warrant exists because LLM systems fail in specific ways, and it was built by, and runs on, the same kind of system. So the risks below come from three levels: the agents it gates, the model inside it, and the model that built it.

The limit of this analysis

This table was drafted by the same model it describes, from its own logs. It can only list failures that someone caught, so the silent ones are missing by construction. Treat it as a proposal, and check it against an independent reader before relying on it.

Do we need a post-LLM architecture? What this build suggests

A hypothesis, not a finding: no belief-state system was built or tested here. This is the replacement map promised in section 01.

The test I would run. Give a persistent belief store and this harness the same cases plus a stream of evidence updates. Compare missed defects, over-holds, cost per decision and how well each explains itself after the fact. If the harness matches on all four, that is a finding too: the problem is engineering, not architecture.

Open questions before anyone builds this

  1. Do conflicts reach costly volume outside agent-native firms, or is staleness the whole problem? Five interviews and one log pull answer this.
  2. Will a real agent framework let money actions be intercepted before commit, across two or more vendors?
  3. What miss rate would finance accept for autonomous credits, and what over-hold rate would support accept?
  4. Who is the daily user the product wins or loses on: the engineer who owns the boundary, or the analyst who rules?
  5. Does a belief store beat a well-run harness on the test above?
Where this plan is weak

1. No customer has confirmed the problem. The evidence is public opinion classified by a model. 2. The results grade themselves. The same model wrote the system and its tests, on synthetic data and a small sample. 3. The gate stands in front of nothing yet. No live agent, no person receiving a question, no proof for the buyer. It demonstrates a mechanism, not a product.
